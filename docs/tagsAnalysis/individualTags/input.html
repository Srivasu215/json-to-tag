Tag Semantic Story & Behavior

The <input> element is the workhorse of HTML forms. It is configured primarily through attributes to create text boxes, checkboxes, passwords, email fields, dates, and number inputs.

Why It Is a Void Element

In standard HTML and in tags.json, allowsChildren: false and allowsTextContent: false. An input does not enclose child tags; its visible value is passed via the value or placeholder attributes.

Allowed Attributes Overview

  • type: Controls input behavior (e.g. text, email, password, number, date).
  • placeholder: Faint hint displayed inside the input until user enters text.
  • value: Pre-populated initial scalar value.
  • name: Identifier submitted with form payloads.
  • disabled / readonly: Interactivity state booleans.
  • required: Browser-native form validation gate.
  • list: Links the input to a <datalist id="..."> for autocomplete suggestions.

Authoring Specifications in json-to-tag

Pattern A: Text / Email Input Paired with <label>

Accessible input specification matching a label's for attribute:

{
  "tagName": "input",
  "classList": "form-control",
  "attributes": {
    "id": "user-email",
    "type": "email",
    "name": "email",
    "placeholder": "name@example.com",
    "required": true
  }
}

Pattern B: Input Linked to Autocomplete <datalist>

Utilizing the list attribute to bind suggestions:

{
  "tagName": "input",
  "classList": "form-control",
  "attributes": {
    "type": "text",
    "name": "browser",
    "placeholder": "Choose your browser...",
    "list": "browser-options"
  }
}
